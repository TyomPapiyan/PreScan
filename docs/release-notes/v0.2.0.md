PreScan inspects a file for maliciousness **before you run it** and a web link's contents **before you download it** — a signal aggregator with an ML score, not a resident antivirus.

> **PreScan is not an antivirus and does not replace your system's built-in protection.** The verdict is informational; the decision to open a file remains yours (§11.4).

**Supported platforms:** Linux x86_64 (Ubuntu 24.04 or newer) and Windows 10/11 x64. ARM is not supported.

## What's new in 0.2.0

- **Cloud file upload, by explicit consent (M8).** A third analysis layer can now upload the file **body** to the cloud (VirusTotal) for a fresh scan when the file is unknown there. It is **off by default** and never automatic: it runs only when you ask — the `--allow-upload` flag or the result-screen button in the GUI — **and** the "Never upload files to the cloud" setting is turned off. A submitted file **leaves your machine in full and cannot be recalled**; per VirusTotal's terms it may be shared with premium customers and its scan report is published to the community. The consent dialog states this in full and does not soften it. See *What leaves your machine* in the README.
- **Links with `--download` now hash-check the downloaded body.** A file fetched from a link is looked up by SHA-256 against the cloud reputation sources, closing a detection gap. A **known-malicious** body makes the link `DANGEROUS`; a **clean** hash does **not** make the link `SAFE` — a URL can serve different content, so the link stays `UNKNOWN` (§8.3).
- **The upload fact is recorded and shown honestly.** The report (HTML/PDF), history, and result screen show a past-tense line — "this file was uploaded to X at \<time\>" — with the time in your **local** zone and an explicit offset (stored internally as UTC). A cached result never reads as "uploading now" and never re-offers an upload.
- **Fixed an ML false positive on non-executable files.** The bundled classifier is an executable-malware model; measurement showed it reliable on Windows **PE** and Linux **ELF** but pure noise on data formats — clean PNG/JPEG/GZIP/text/JSON files scored 0.6–0.96 and could be flagged `SUSPICIOUS`. The ML stage now runs **only on PE/ELF** and is reported "does not apply to this file type" otherwise; its score never reaches the report or the verdict for those files. This defect is present in **v0.1.0** as well, so upgrading fixes it. A clean non-executable that an authoritative engine (e.g. ClamAV) cleared now reaches `SAFE` instead of being wrongly held at `SUSPICIOUS`.
- **Fixed a false positive on ordinary PDFs.** A PDF that declared an automatic action (`/OpenAction`) was flagged `SUSPICIOUS` — but measurement over 400 clean system PDFs found `/OpenAction` on 1% of them and none of those carried any active content: a great many benign PDFs set it merely to fix the initial view. An automatic action alone is now **informational only** and never moves the verdict; escalation is reserved for genuinely active content — embedded JavaScript, an external `/Launch`, an embedded file, or a form submission (`/SubmitForm`) — which clean PDFs essentially never carry. Detection of the dangerous cases is unchanged and, for `/Launch` and `/SubmitForm`, improved. Present in **v0.1.0** as well.

## ⚠️ Behaviour change since 0.1.0: detection ratio may differ

The hash-reputation denominator changed. In 0.1.0 the VirusTotal `last_analysis_stats` total counted **all** stat keys; from 0.2.0 it counts only the **four verdict keys** (`malicious`, `suspicious`, `harmless`, `undetected`). This makes the "known & clean" and malicious-ratio decisions more accurate, but it means the **share of detections can differ from 0.1.0** on the same file. This is expected, not a regression.

## Storage migration

The history database gains two columns — `uploaded_to` and `uploaded_at` — by an **additive** migration (`ADD COLUMN` only; no table is dropped or rewritten). A **dated backup of the database is made before the migration runs**; if the backup cannot be created the migration does not run at all, and the three most recent backups are kept. Older reports cached before these fields existed continue to load unchanged.

## Install

**Ubuntu / Debian (24.04+), the `.deb` (recommended):** apt resolves the runtime libraries itself.
```bash
sudo apt install ./prescan_0.2.0_amd64.deb
prescan            # GUI    |    prescan scan <file|url>    # CLI
```

**Ubuntu, the portable AppImage:** an AppImage declares **no** dependencies, so unlike the `.deb` it does *not* pull anything in. The Qt GUI needs your system's GL/GLib libraries to already be present — on a normal desktop they are; on a minimal or server install they are not, and a missing one shows up as an ImportError, not a bug in PreScan. Install them once if needed:
```bash
sudo apt install libgl1 libegl1 libglib2.0-0 libxkbcommon0 libdbus-1-3
chmod +x PreScan-0.2.0-x86_64.AppImage
./PreScan-0.2.0-x86_64.AppImage
```

**Windows 10/11 x64:** run `PreScan-Setup-0.2.0.exe` and follow the installer.

> ⚠️ **The Windows installer is not code-signed.** SmartScreen will show a "Windows protected your PC" warning — click **More info → Run anyway**. Verify the download against `SHA256SUMS` below before running.

## The ML model is a separate download

The classifier (`model.onnx`) is **not** bundled (spec §3.4). Fetch it once — it is downloaded from its own pinned release and its SHA-256 is verified:
```bash
prescan update-model
```
Until then the ML stage degrades gracefully and file scans return `UNKNOWN` instead of an ML-backed verdict.

## ClamAV is optional and installed separately

ClamAV is an optional engine; its binaries are **not** bundled (GPL-2.0). PreScan degrades gracefully without it. Install from <https://www.clamav.net/downloads>:
- **Ubuntu:** `sudo apt-get install clamav clamav-daemon && sudo systemctl enable --now clamav-daemon`
- **Windows:** install the official package, run `freshclam`, start the `clamd` service.

Microsoft Defender is used automatically on Windows; on Linux the Defender stage is reported unsupported and skipped.

## Optional online sources (API keys)

The cloud reputation/URL sources are optional and off until you add a key; see the README for how to obtain and store them. Note: **Google Safe Browsing and the VirusTotal Public API are free for non-commercial use only** (§11.4). The public VirusTotal key is rate-limited to **4 requests per minute and 500 per day** — and a single cloud upload spends, out of that 500, one reputation request, one submission, and up to a dozen polling requests, so a handful of uploads can consume a large slice of the daily quota.
